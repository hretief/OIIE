Guiding principles
One repo, one solution → Copilot sees the whole SANDBOX → CIR → ISBM flow.
Deploy independently → keep separate infra + path-filtered CI/CD per app.
Extract shared contracts → eliminate the CCOM/ISBM/BOD duplication you have today.
Solution folders + .slnf filters → full context for Copilot, focused loading when you want it.

How you keep independent deliverables

This is the key part — single solution does not mean single deployment.

1. Path-filtered GitHub Actions. Each app deploys only when its own code (or a shared lib it depends on) changes:

YAML
1
# .github/workflows/cir.yml
2
on:
3
push:
4
paths:
5
- 'src/cir/**'
6
- 'src/shared/**' # CIR depends on shared contracts
7
- 'infra/cir/**'
Show more lines

2. Separate infra folders — each deliverable owns its Bicep modules and deploy scripts, so releases stay decoupled.

3. Project references for shared libs (simplest), or promote src/shared/* to versioned NuGet packages on a private feed if you want hard version boundaries between apps. Start with project references; move to NuGet only if teams need to pin versions.

Add schemas/ and docs/ as Solution Items — that way Copilot Enterprise indexes your XSDs and architecture.md as context, so questions like "trace a publication request from SANDBOX through CIR into ISBM" get answered against real contracts.
